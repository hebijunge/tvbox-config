# 复合 group 名方案（"品类-类型"格式）

> 状态：待确认

## 背景与问题陈述

- 当前 group 字段是扁平字符串，比如 "影视"、"点播"、"直播"。
- TVBox 客户端会把 group 当分类 tab 展示；扁平 group 粒度太粗，用户在 4048 个源里找片时要翻很多。
- 把 group 升级为 "品类-类型" 复合名（如 "电影-CMS"、"动漫-spider"），让 tab 更细。

## 方案设计

### 9.1 group 命名格式

```
group = "<品类>-<类型>"
```

示例：
- `电影-CMS`
- `电影-spider`
- `剧集-CMS`
- `动漫-drpy`
- `综艺-聚合`
- `纪录片-CMS`
- `体育-直播`

### 9.2 品类词表

`config/category_vocab.json`（与 coverage-analysis 复用）：
- 电影 / 剧集 / 综艺 / 动漫 / 纪录片 / 体育 / 少儿 / 其他

### 9.3 客户端兼容性评估

| 风险点 | 评估 |
| --- | --- |
| group 名含 "-" | TVBox 客户端对 "-" 无特殊解析，应安全；需在主流分支实测 |
| group 数量 | 当前 group 数预计 ~20（6 品类 × 3 类型 - 空组合），客户端 tab 一般支持到 30+，需实测 |
| 用户收藏 | 用户按 group 收藏的源，group 改名后收藏可能丢失或归到"未分组"——**这是最大风险** |
| 旧配置兼容 | 老用户 tvbox 客户端缓存的 group 列表不会自动更新，需等客户端刷新配置 |

### 9.4 主流 TVBox 分支兼容性

| 分支 | group 长度限制 | 含特殊字符 | 需实测 |
| --- | --- | --- | --- |
| TVBox（原版） | 无硬限，UI 截断 | 安全 | 是 |
| TVMe / 秋英 | 待实测 | 待实测 | 是 |
| 其它 fork | 待实测 | 待实测 | 是 |

## 影响评估

| 面 | 影响 |
| --- | --- |
| tvbox.json | group 字段值变了 |
| 用户端 | tab 更细，但老用户收藏可能漂移 |
| 体积 | group 名变长，tvbox.json 略增（< 5%） |
| 测试 | 必须在至少 2 个主流客户端实测 |

## 实施步骤（分阶段可回滚）

1. **阶段 1**：写 `scripts/group_compound.py`，把现有 group 映射成复合名；同时输出 `tvbox_compound.json` 副本（不替换主产物）。
2. **阶段 2**：在 TVBox 客户端手动导入 `tvbox_compound.json`，实测 tab 展示、搜索、收藏。
3. **阶段 3**：确认无误后切为默认；保留 `--legacy-group` 入口。

## 回滚方案

- `LEGACY_GROUP=1` 环境变量切回扁平 group 名。
- group 映射表 `config/group_map.json`，改回旧值即可。

## 需用户确认的决策点

1. 复合名格式 "品类-类型" 是否接受？还是用 "/" 或其他分隔符？
2. 是否接受老用户收藏漂移？（这是高风险项，可能需要过渡期双写）
3. 哪些客户端是必须兼容的？（TVBox 原版、TVMe、其他？）
